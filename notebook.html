Keep the useful bits.

Small tests, unexpected problems, and the decisions that move a build forward. These first entries are drawn from my 2024 Fab Academy work; newer notes will build on the same practice.

Fab Academy 2024 / Electronics

Make a failure visible

After eight board iterations, status LEDs became one of the most useful debugging tools in the system. They made it easier to tell whether a subsystem was running before reaching for another instrument.

Question

How can I tell what the circuit is doing while the full robot is assembled?

Test

Use visible indicators while checking connections and running separate code loops.

Takeaway

Design for observability. A small signal can save a lot of blind debugging.

Fab Academy 2024 / Fabrication

A bowtie for the laser cutter

The 3D-printed bowtie was not giving the finish I wanted, so I moved the decorative part to the laser cutter and kept a printed adaptor for the servo. That split made the bowtie easy to swap.

Change

Separate the visible part from the mechanism that attaches it to the robot.

Result

Laser-cut versions in blue acrylic and walnut fit the same printed adaptor.

Takeaway

Modularity can come from choosing the right process for each part.

Fab Academy 2024 / Integration

Scope down, keep the interaction

A fully mobile robot and spoken interaction were part of the original ambition. The integration work made clear that a stable desktop build with a moving head and responsive face was a better target for the time available.

Constraint

Many subsystems still needed to work together in a short build window.

Decision

Defer roaming and speech; focus on the head, screen, sensor, motor, and servo.

Takeaway

Reducing scope is useful when it preserves the core experience and makes integration testable.
